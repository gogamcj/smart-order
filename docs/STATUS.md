## 2. 실행한 테스트 (1단계)

실행 환경: Node 22.22, PostgreSQL 16.15 (로컬), Vitest 3.2.4. 명령 `pnpm test`. 결과 49 통과 / 0 실패.

| 파일 | 내용 | 결과 |
|---|---|---|
| `migrations.test.ts` | 신규 설치, 재실행 멱등, 추가 마이그레이션만 적용, 체크섬 변조 거부, 실패 시 롤백, RLS 누락 테이블 없음 | 6/6 |
| `tenant-isolation.test.ts` | 타 업체 주문·하위 데이터 조회 차단, 메뉴 수정·삭제·변조 insert·소유 이전 차단, 주문 상태 변경·환불 차단, 직원·QR 접근 차단, 컨텍스트 없으면 0행, 복합 FK, 고객 간 격리, 고객 쓰기 제한, 승인 상태 자가 변경 차단, 시스템 테이블 접근 차단, 표시 번호 함수 차단 | 15/15 |
| `orders.test.ts` | 미결제 확정 차단, 허용 전이만, 이력·아웃박스 기록, 낙관적 잠금, 금액 불변, 중복 주문 키, 라인 금액 검증, 스냅샷 보존, 미승인·정지·접수중지 업체 주문 차단, 표시 번호, 할인가 검증 | 11/11 |
| `payments.test.ts` | 결제 요청 ID 중복, 승인 금액 불일치, 이중 결제, 웹훅 이벤트 중복, 부분→전체 환불 상태 갱신, 환불 한도·멱등 키, 완료 환불 재변경 차단, 미결제 환불 차단, 환경 불일치 차단, 결제 금액 불변 | 10/10 |
| `qr-and-audit.test.ts` | 토큰 해석, 없는 토큰, 재발급 후 이전 토큰 무효·테이블당 1개, 비활성 테이블·정지 업체, 짧은 토큰 거부, 감사 로그 수정·삭제 차단, 과금 비활성 | 7/7 |

테스트 중 발견해 고친 문제: 같은 멱등 키로 환불을 재시도하면 한도 검사 트리거가 먼저 실행되어 `ON CONFLICT` 로 기존 환불을 돌려주지 못하고 “한도 초과” 오류가 나던 문제 → 트리거가 같은 키 재시도를 감지하면 한도 검사를 건너뛰도록 수정 후 재실행 통과.
