### 브라우저 실동작 점검 — 13/13 통과, 콘솔 오류 0건
실제 API 서버 + 실제 PostgreSQL + 세 화면을 빌드해 띄우고 Chromium 으로 조작(고객은 iPhone 13 화면 크기, 해시 주소). 가짜 PG·개발용 로그인 사용. 결과: [test-results/stage2-e2e-smoke.txt](test-results/stage2-e2e-smoke.txt), 화면: [screenshots/stage2](screenshots/stage2), 방법: [e2e/README.md](../e2e/README.md)

점검 중 발견해 고친 문제:
- 결제 승인 직후 고객 주문 화면이 이전에 읽어 둔 "결제 대기" 상태로 보이던 문제 → 결제 확정 후 주문 정보를 다시 읽도록 수정
- 최고 관리자가 승인해도 이미 열려 있던 업체 화면에 "승인 대기" 안내가 남던 문제 → 업체 상태를 1분마다 다시 읽도록 수정
- QR 진입 화면에서 쿠키가 생기기 전에 주문 컨텍스트를 먼저 조회해 403 이 나던 문제 → QR 진입 중에는 조회하지 않도록 수정

### 테스트 중 고친 서버 문제
- 업체가 메뉴 옵션 구성을 바꿀 때, 과거 주문이 참조하는 옵션 때문에 저장이 실패하던 문제 → 주문 스냅샷의 옵션 참조만 끊도록(`ON DELETE SET NULL`) 마이그레이션 0007 에서 수정. 과거 주문의 옵션 이름·가격은 유지(테스트로 확인)
- `.env` 의 빈 값(`KEY=`)이 잘못된 값으로 처리되던 문제 → 빈 값은 설정 안 함으로 처리

## 5. 외부 설정이 필요한 항목

[07-external-accounts.md](07-external-accounts.md) 참고. 2단계에서 바로 필요한 것:
1. **카카오**: Client Secret 활성화 값, Redirect URI 등록(`https://api.<도메인>/api/auth/kakao/callback`). REST API 키는 받았고 서버 환경변수로만 사용합니다(저장소에 없음).
2. **도메인 + Cafe24 웹호스팅 + 백엔드 서버**: 화면과 API 가 같은 등록 도메인 아래 있어야 로그인이 유지됩니다(06-deployment).
3. **PG 결정·계약**(모델 B 지급대행) — 3단계 시작 조건.
